API reference

ODSFiles.ODSFiles — Module
ODSFiles

Read and write OpenDocument spreadsheets (.ods, .fods, .ots) in pure Julia.

The public API mirrors XLSX.jl wherever that is reasonable (see records/api-divergence.md in the workspace).

source
ODSFiles.openods — Function
openods(source; mode="r", enable_cache=true) -> ODSFile
openods(f::Function, source; mode="r", enable_cache=true)

Open an OpenDocument spreadsheet (.ods, .fods or .ots, detected from the content) from a file path or an IO. The do-block form passes the file to f and returns what f returns.

content.xml is read once, and the sheets are located without being parsed.

  • enable_cache=true: a sheet is parsed into memory the first time one of its cells is read; later reads use that copy.
  • enable_cache=false: every read scans the sheet again, keeping nothing, and stops after the last row it needs. Use it with eachrow to stream a large sheet.

Modes, as in XLSX.jl:

  • "r": read only.
  • "rw": read and edit; save with saveods or writeods. Saving patches the original file: everything ODSFiles does not edit is kept as it was (D-023).
  • "w": start a new, empty spreadsheet (with one sheet, Sheet1) that will be written to source; an existing file there is not read.

Writing modes need enable_cache=true. With the do-block form, a file opened for writing is saved to source after f returns (not if f throws).

See also readods, newods.

ODSFiles.writeods — Function
writeods(dest, xf::ODSFile; overwrite=false, version="1.4") -> path or nothing

Write xf to dest, a file path or an IO.

  • The format follows the extension of a path: .ods, .ots (a template) or .fods (flat XML). Writing to an IO keeps the format the file was read in (.ods for a new one).
  • A file that was read is written by patching it (D-023): what ODSFiles does not edit is kept exactly as it was. It can be written as a template or a document, but not converted between zipped and flat XML yet.
  • A new file is written in ODF 1.4, or 1.3 with version="1.3" (D-006).
  • display_text=false leaves out the display text (text:p) of the number, date, time and boolean cells that ODSFiles writes; readers recompute it from the value. Files are then smaller (about half, for numeric data) and faster to write (D-029).
  • An existing file at dest is only replaced with overwrite=true.

A path becomes the file's new source (for saveods). Returns the absolute path, or nothing for an IO.

Reading cells

ODSFiles.SheetCore.getdata — Function
getdata(sheet, ref)
getdata(sheet, row, column)
getdata(sheet)

Values from a worksheet: a scalar for a single cell, a Matrix{Any} for a rectangular range, or a vector of matrices for a list of ranges. Empty cells, empty strings and errors read as missing.

ref is a cell or range ("A1", "A1:C4", "A:B", "1:4", "A1:A4,C1"), a sheet-qualified one in LibreOffice's or Excel's notation ("Sheet1.A1:C4", "Sheet1!A1:C4"), or a defined name. Rows and columns can also be integers, unit ranges, step ranges, vectors or :. For whole columns or rows, the other extent is the sheet's get_dimension.

Indexing a Worksheet calls getdata: sheet["A1"], sheet[1:3, 2], sheet[:].

The value types are described in Cell: Int64 or Float64 for numbers, String, Bool, Date or DateTime, and Time (or a CompoundPeriod for 24 hours or more).

ODSFiles.get_dimension — Function
get_dimension(ws::Worksheet; allow_load=true) -> CellRange

The smallest range holding every cell with a value or formula. ODS files do not record it, so it is computed from the sheet (the cache, or a scan without the cache). An empty sheet gives A1:A1, as in XLSX.jl. With allow_load=false, an unread sheet gives A1:A1 without being read.

ODSFiles.Cell — Type
Cell

A cell read from a worksheet. Fields:

  • ref::CellRef: its position
  • datatype::Symbol: the ODF value type: :float, :percentage, :currency, :date, :time, :boolean, :string, :error, or :empty (a formula with no result, or a covered cell)
  • value: its value, as getdata returns it
  • formula: the stored formula ("of:=[.A1]*3"), or nothing; getFormula gives it in LibreOffice's notation
  • style::String: the name of its effective cell style
  • currency: the currency code of a currency cell ("GBP"), else nothing
  • error: the displayed text of an error result ("#DIV/0!", "Err:502"), else nothing
  • colspan, rowspan: the size of a merge whose top-left cell this is (1 otherwise)
  • covered::Bool: whether the cell is hidden by a merge

ODSFiles.getFormula — Function
getFormula(sheet, ref; raw=false) -> Union{String, Nothing}
getFormula(sheet, row, col; raw=false)
getFormula(xf, "Sheet1.A1"; raw=false)

The formula of a cell, as LibreOffice shows it ("=SUM(A1:B2,1)", "='My sheet'.A1*2"), or nothing if the cell has none. With raw=true, the formula as stored in the file ("of:=SUM([.A1:.B2];1)").

The UI notation follows LibreOffice with its en-US settings: , between function arguments and between the columns of an inline array, ; between its rows. Formulas written in another namespace than OpenFormula (such as msoxl:) lose their prefix and are otherwise returned unchanged.

eachrow(sheet::Worksheet)

ODSFiles.SheetCore.CellRef — Type
CellRef(n::AbstractString)
CellRef(row::Int, col::Int)

A CellRef represents a cell location given by row and column identifiers.

CellRef("B6") indicates a cell located at column 2 and row 6.

These row and column integers can also be passed directly to the CellRef constructor: CellRef(6,2) == CellRef("B6").

Finally, a convenience macro @ref_str is provided: ref"B6" == CellRef("B6").

Examples

cn = SheetCore.CellRef("AB1")
println( SheetCore.row_number(cn) ) # will print 1
println( SheetCore.column_number(cn) ) # will print 28
println( string(cn) ) # will print out AB1
println( cellname(cn) ) # will print out AB1

cn = SheetCore.CellRef(1, 28)
println( SheetCore.row_number(cn) ) # will print 1
println( SheetCore.column_number(cn) ) # will print 28
println( string(cn) ) # will print out AB1
println( cellname(cn) ) # will print out AB1

cn = SheetCore.ref"AB1"
println( SheetCore.row_number(cn) ) # will print 1
println( SheetCore.column_number(cn) ) # will print 28
println( string(cn) ) # will print out AB1
println( cellname(cn) ) # will print out AB1

ODSFiles.SheetCellRef — Type
SheetCellRef{S<:RefStyle}(ref::AbstractString)
SheetCellRef{S<:RefStyle}(sheet::AbstractString, cellref::CellRef)

A cell on a named sheet: a CellRef together with the name of its sheet, in the fields sheet and cellref. S is the notation it is parsed from and shown in (RefStyle); each back end binds SheetCellRef to its own style.

SheetCellRef{ExcelStyle}("Sheet1!B2") refers to cell B2 on sheet Sheet1. A sheet name containing spaces or other special characters is quoted, as in Excel: SheetCellRef{ExcelStyle}("'Sheet 1'!B2"), which SheetCellRef{ExcelStyle}("Sheet 1", CellRef("B2")) also gives. In ODFStyle the same cell is Sheet1.B2 and 'Sheet 1'.B2.

Examples

julia> r = SheetCore.SheetCellRef{SheetCore.ExcelStyle}("Sheet1!B2")
Sheet1!B2

julia> SheetCore.SheetCellRef{SheetCore.ODFStyle}("'My sheet'.B2")
'My sheet'.B2

julia> r.sheet
"Sheet1"

julia> r.cellref
B2

Tables

ODSFiles.readtable — Function
readtable(source, [sheet, [columns]]; [first_row], [column_labels], [header],
          [infer_eltypes], [stop_in_empty_row], [stop_in_row_function],
          [keep_empty_rows], [normalizenames], [missing_strings]) -> DataTable

Read a table from a file path or IO without keeping the sheet in memory: gettable on sheet (a name or number; the first sheet if not given) of the file opened with enable_cache=false.

Use first_row to give the first row of the table (its header, if header=true). Without it, the table starts at the first row with data in its first column.

header (default true) says whether the first row holds the column labels. Without a header, and without column_labels, the labels are the column letters.

column_labels gives the labels as a vector of Symbols or strings.

normalizenames=true turns the labels into valid Julia identifiers.

missing_strings gives strings (one, or a vector) to read as missing.

infer_eltypes (default true) gives each column the narrowest element type of its values; otherwise columns are Vector{Any}.

stop_in_empty_row (default true) ends the table at the first empty row. stop_in_row_function is a function of a TableRow returning true at the row that ends the table (that row is left out).

keep_empty_rows (default false) keeps rows whose values are all missing between the first and the last row of the table.

enable_cache is accepted for compatibility with XLSX.jl and ignored.

Writing

ODSFiles.setdata! — Function
setdata!(sheet, ref, value)
setdata!(sheet, row, col, value)
sheet[ref] = value
sheet[row, col] = value

Write value into a cell, or into every cell of a range. The file must be writable (openods with mode="rw" or "w", or newods).

  • value may be a number, string, Bool, Date, DateTime, Time, a period (a duration), or missing/nothing to empty the cell.
  • A matrix fills a range of its size.
  • A vector fills a row (dim=2, the default) or a column (dim=1) from a cell, or a one-row or one-column range.
  • ref takes the forms of getdata: "B2", "B2:D4", "Sheet1.B2", "Sheet1!B2", integers and ranges.

A cell keeps its style when that style's format fits the new value. Otherwise dates, date-times, times and booleans get ISO formats, and numbers and text the Default style (D-024, D-027).

source
ODSFiles.setFormula — Function
setFormula(sheet, ref; val, raw=false)
setFormula(sheet, row, col; val, raw=false)

Write a formula into a cell, or into every cell of a range (the same formula in each). val is in LibreOffice's notation, as getFormula gives it: "=SUM(B1:B3,'My sheet'.A1)". It is stored as OpenFormula (of:=SUM([.B1:.B3];['My sheet'.A1])) (D-025). With raw=true, val is stored as given, and must be a stored formula such as "of:=[.A1]*2".

The cell's value is left empty: LibreOffice computes it when it opens the file (F-028).

ODSFiles.writetable — Function
writetable(filename, data, columnnames; overwrite=false, sheetname="", anchor_cell="A1", streaming=false)
writetable(filename, table; overwrite=false, sheetname="", anchor_cell="A1", streaming=false)

Write tables to a new file (a path or an IO), one per sheet, each with a header row. The format follows the file's extension (.ods, .ots, .fods). An existing file is only replaced with overwrite=true. With streaming=true, rows are written as they are produced, in bounded memory (streamods); anchor_cell is then not available. display_text=false leaves out the display text of number, date, time and boolean cells (smaller files, faster writes; see writeods).

ODSFiles.streamods — Function
streamods(f, dest; overwrite=false, version="1.4")

Write a new file to dest (a path or an IO) row by row, in bounded memory. f gets a StreamWriter: add sheets with addsheet!(s, name; columns) (a header row) or addsheet!(s, name, table) (a Tables.jl table, header and rows), and write rows with writerow! and writerows!. The format follows the extension (.ods, .ots; flat .fods is not streamed). display_text=false leaves out the display text of number, date, time and boolean cells, as in writeods.

streamods("big.ods") do s
    sh = addsheet!(s, "data"; columns = ["n", "square"])
    for n in 1:1_000_000
        writerow!(sh, (n, n^2))
    end
end

The shared core

The format-independent parts of ODSFiles (references, tables, number formats, dates) live in a submodule meant to be shared with XLSX.jl in future. It is not part of the public API.

ODSFiles.SheetCore — Module
SheetCore

The format-independent core shared by the spreadsheet back ends (D-001): cell references and ranges, tabular data and Tables.jl input, number formats and displayed text, date serial numbers, text widths for autofit, colours, and reading zip parts.

It knows nothing about ODF or OOXML. It is developed inside ODSFiles.jl, and is kept self-contained so that it can later become a package of its own that XLSX.jl can also use (see records/core-migration.md in the workspace). Most of its code is adapted from XLSX.jl 0.13.4 (MIT License, Copyright (c) 2018-2026 Felipe Noronha Tavares and other contributors); each file says what it came from and what changed.

Its names are the ones XLSX.jl uses, so that adopting it is a matter of imports.
